Golden Dataset grain and contract

  • Grain: one row per canonical account × observed month.
  • Key: (account_id, month); must be unique.
  • Payment rule: latest event per payment ID, then latest per transaction reference; blank references use a payment-ID surrogate.
  • Cash rule: only final SUCCESS events contribute; failed, pending and reversed statuses contribute zero.
  • Lineage: raw CSVs are preserved; canonical outputs and checks are regenerated by python src/run_all.py.

Do not mistake a technical rule for source truth

  • 3,407 conflicting transaction-reference groups were flagged in the forensic output; source-ledger adjudication is required.
  • Timezone semantics, vendor disposition crosswalks and agent identity conflicts require source-owner confirmation.
  • The available snapshot outstanding balance is not a historical month-opening denominator; recovery-rate trend remains unvalidated.
  • Cleaning impact shows how the chosen rule changes results, not that every removed amount was fraudulent or invalid.

Reproducibility and acceptance checks

Run python src/run_all.py then pytest -q. Before production, reconcile canonical payment events and net cash to Finance’s ledger and sign off the tie-break rule for same-time conflicts.
